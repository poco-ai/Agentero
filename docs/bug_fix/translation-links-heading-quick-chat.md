# 全文译文丢链接、标题缩字、快速对话高亮

**状态**：已修复（#732）。

## 现象

全文翻译之后，原文里的方括号引用、作者-年份、Figure / Section 交叉引用和 Markdown 链接要么被模型改写，要么还在译文里但点不进去。标题译文比正文还小，层级没了。快速对话发出问题后，选区黄框只在 hover 页边针（从而打开卡片）时出现；译文打开时这框还盖在英文坐标上，被译文纸面挡住。

## 原因

- `mask.ts` 只保护公式、URL 和 DOI。引用标记会进模型。译文纸面和字形盖住 `z-2` 的英文 Link 命中区；把命中区抬到字形之上会挡住译文划选。
- 标题和正文走同一套「装进原框」字号。更长的译文先被估小，DOM 度量再二分到 1px。
- 快速对话高亮只在卡片打开时画，而且是 `z-1` 的琥珀色英文框。页边针要 hover 才打开卡片。译文上划选的可见区域没有写进 ask anchor。

## 修复

- 译前把方括号引用、作者-年份、Figure / Table / Section / Equation 等交叉引用、URL 和 Markdown 链接换成 `⟦n⟧`，回填后只在这些标记上重挂原来的 Link。英文命中区仍留在 `z-2`。
- 标题按原文框的字号排，不按更长译文缩小。装不下时向下加高（最多约 2.75×，停在版面框前）。DOM 校验对标题最多收到初始字号的 90%。
- 发出问题后的 ask 选区用与批注相同的黄色、`z-5`、`multiply` 常驻绘制。译文上开始的快速对话把划中框存进 `anchor.translatedRects`；译文显示时画这套框，并把页边针的 y 移到框顶。还没输入内容的空草稿关闭卡片时直接丢弃，不留下页边针或选区高亮；已输入但未发送的草稿保留页边针、选区高亮和输入内容，重新打开可继续。此前的实现会一律保留到下一次快速对话。
