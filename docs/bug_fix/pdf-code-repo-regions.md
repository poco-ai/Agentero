# PDF 代码仓库不要扫进参考文献

2026-11-03。论文的 GitHub 仓库可能在摘要、首页脚注或文末，脚注经常只是一个可点击注释，页面上印出来的不是 URL。只扫第一页会漏掉文末的仓库；整篇全文扫又会把参考文献里别人的仓库写进 `code_repo`。

## 根因

链接注释和印出来的 URL 都要收，但位置决定它是不是这篇论文自己的仓库。参考文献条目、`et al.` 旁边的链接，不能和摘要或「code is available」脚注同等对待。用户在编辑元信息里改过或清空的值，重新打开时也不该被自动结果盖回去。

## 修复

按摘要、首页脚注、文末（参考文献标题之前）的顺序打分，其余正文只有带着代码发布这类表述才采纳。仓库主页高于 issue / commit 子页面，结果规范成 `https://github.com/{owner}/{repo}`。`code_repo_manual` 在用户写入该字段时置位，扫描看到它就停。
