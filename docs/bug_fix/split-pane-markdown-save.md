# 同一笔记的两个分屏会互相覆盖整篇

**状态**：已修复
**影响面**：同一窗口里把同一份 Markdown 分到两个面板。渲染视图和源码视图都会自动保存整份文件。
**相关代码**：

- `src/lib/workspace/persistence.ts` — 上次写入按路径记下内容，并记下是哪个面板写的
- `src/lib/workspace/tabs/notes-split.ts` — 保存后刷新干净的兄弟面板，拦住仍有草稿的面板
- `src/components/editor/markdown-editor.tsx` — 冲突横幅：保留草稿或载入磁盘新版
- `src/components/editor/hooks/use-markdown-persistence.ts` — 冲突期间不自动保存，保留草稿时放行这一次写入

---

## 1. 问题现象

两个面板都从版本 A 开始。面板 1 改了第一段并自动保存成 B。面板 2 仍基于 A 改最后一段，随后自动保存。磁盘上只剩面板 2 写出的整份内容，面板 1 的修改消失，而且没有冲突提示。

## 2. 根因

`lastOwnWriteByPath` 只按路径记录「本窗口刚写过的正文」。面板 2 保存时看到磁盘上的 B 等于这条记录，就把它当成自己的写入，冲突检查放行，再用旧基线整份覆盖。

同路径 tab 的 seed 会更新，但已经挂载的编辑器只在 `reloadKey` 变化时重载，所以干净的另一面板也停在旧内容。

## 3. 修复

- 写入记录带上面板 id。同一面板稍后补写仍可放过自己的回声；另一个面板看到这份正文则视为冲突，不再写入。
- 保存成功后：没有未保存改动的兄弟面板更新 seed 并增加 reload key，就地换成磁盘内容；已有草稿的兄弟面板只标上 `markdownConflict`，不改 seed、不重载。
- 冲突横幅在解决前挡住自动保存、`⌘S` / `Ctrl+S` 和卸载 flush。保留草稿会先把磁盘新版记成基线，再把草稿整份写回去；载入磁盘新版在点击时重新读盘，只替换当前面板。
- toast 只剩「载入磁盘版」一个动作，和横幅的载入共用 `applyMarkdownConflictChoice`；「保留草稿」只在横幅里出现，点一次就写盘，不允许把放行权限留到下一次自动保存。
- 本窗口自己的 watcher 回声仍按正文提前返回，避免把这次保存再报成外部修改。不同窗口不在这次范围内。
- 外部改盘走 `seedTabs` 时，分屏 `NOTES.md` 的 id 不是论文目录或笔记的规范 id，也要算作这篇笔记的所有者。

## 4. 和 #970 的取舍

#970 已经合进 `main`：按面板记录写入、拦住脏面板，并用 toast 提示。「保留草稿」在那条 toast 里只是关掉提示，冲突标记还在，草稿之后也不能写回磁盘。这里在那套机制上加了编辑器常驻横幅：保留草稿会明确覆盖磁盘新版，载入磁盘新版只重载当前面板。干净兄弟面板的重载仍按块复用，不整篇重挂。
