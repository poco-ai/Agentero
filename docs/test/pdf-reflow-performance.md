# PDF 翻译重排性能（#1188）

## 测量口径

Apple M3，Vite dev，前台 Chromium，用 #1188 的 `2602.01326`（18 页）、相同的本地字符 IR（15 页）和已保存译文（232 段），不发翻译请求。对照 `beeff4736` 的构建函数与新构建函数；两边使用同一 PDFium 实例，交错运行各 3 次，计时从函数调用到 PDF 字节返回。原版单页场景调用 `buildReflowPdf`，新版调用 `buildReflowPage`；全文两边都调用 `buildReflowPdf`。此探针不包含预览出图、网络、UI 合成或 Vault 写入。

主线程每 16 ms 设一个计时器，记录相邻回调的最大间隔；这是事件循环停顿代理，不是阅读器 FPS。输出用 `PDFDocument.load` 检查页数；解析检查不纳入耗时。

| 指标 | 改前 | 改后 |
| --- | ---: | ---: |
| 单页构建耗时（ms，3 次） | 4106 / 2400 / 1716 | 3725 / 2046 / 1826 |
| 全文构建耗时（ms，3 次） | 9399 / 7574 / 10038 | 6928 / 5473 / 9306 |
| 单页主线程最大间隔（ms，3 次取最大） | 3657 | 22 |
| 全文主线程最大间隔（ms，3 次取最大） | 3244 | 64 |
| 单页写出 PDF 页数 | 18 | 1 |
| 全文写出 PDF 页数 | 18 | 18 |

中位数：单页 **2.40 → 2.05 s**（约 −15%），全文 **9.40 → 6.93 s**（约 −26%）。三次新版单页与三次全文都没有超过 100 ms 的计时器间隔。真实论文用到两种 CJK 字体，全文输出只从 **25.98 → 25.70 MB**；另用 18 页同尺寸的合成文档（每页常规 CJK，不用粗体），原生 WKWebView 输出 **19.77 → 9.16 MB**。字体字节节省取决于实际用到的字形样式，输出大小不能替代内存测量。

## 生命周期与桌面验证

- 在两种 WebView 的构建探针中，阅读引擎启动 2 个 Worker，写出增加 1 个；关闭阅读引擎并经过写出空闲期限后归零。按代码计算，后台全部活跃时，PDFium/编码/写出这一条链路的上限由 9 个降为 5 个每 WebView（不含引用解析、ONNX 或 Rust 子进程）。
- 原生 macOS `pnpm tauri dev` 使用独立临时 Vault 打开同一原文，`pdf_first_page` 成功记录 **2534 ms**。这是打开验证，不是首屏性能 A/B。原生 WKWebView 独立探针验证了新旧构建、页数和 Worker 回收；窗口进入后台时计时器有约 1000 ms 节流，因此不用该组宣称原生交互延迟。
- 使用 `AGENTERO_REFLOW_FONT` 启用真实字体和 PDFium 裁切回归，覆盖公式/链接、缓存、重排、页数和后台翻译；本地额外覆盖单页不触发整篇、按需导出、排队/运行取消及后台引擎最后一个持有者释放。新增用例只用于本地验证。

下一轮对比桌面交互、原生进程峰值和空闲内存：同一 Vault 副本、同一 PDF、同一翻译服务，分别跑无缓存/热缓存、连续单页/全文、滚动与取消，记录 `pdf.reflow.prepareWrite`、`pdf.reflow.write`、`pdf.reflow.render`、首个可见译文及内容进程内存，并取可见窗口的最大主线程间隔。不要把本轮数据外推到 Windows、其他页面或翻译网络耗时。

## 整页位图缓存

2026-11-19，Apple M3 / Chromium，复用相同的 18 页 `2602.01326` 译文与 PDFium 引擎，不请求翻译服务。两个版本接收同一次真实 PDFium 渲染的 BMP 大小；以 DPR=2 和固定缩放顺序访问 18 页，每次离开前页后处理下一页。峰值按缓存中不同页的 `Blob.size` 加总；回翻命中数取最后访问的四页，关闭后统计该文档的缓存剩余。不是内存分配模拟，也没有把 Blob 字节当成进程 RSS。

| 指标 | 只限 24 页 | 24 页 / 32 MiB + 按文档清理 |
| --- | ---: | ---: |
| 100% 缩放，缓存峰值（MiB） | 133.1 | 29.6 |
| 200% 缩放，缓存峰值（MiB） | 532.5 | 29.6 |
| 200% 缩放，关闭后的缓存保留（MiB） | 532.5 | 0 |
| 100% 缩放，回翻命中 | 4 / 4 | 4 / 4 |
| 200% 缩放，回翻命中 | 4 / 4 | 1 / 4 |

可复用位图峰值分别减少约 **78%**、**94%**。高倍缩放远距离回翻更容易重新出图，本样本 200% 的 PDFium 单页渲染中位数为 **117 ms**（不含排队和浏览器解码），不是滚动延迟。清晰度与可见页调度不变。用同一原生 `Blob` URL 供挂载图层和缓存持有，确保淘汰不会让当前画面丢图。

在 Chromium 的 StrictMode 阅读路径中，真实重排译文成功出图；替换隐藏译文文档后，旧文档与其整页位图同时消失，新页正常出图，卸载后缓存归零。macOS `pnpm tauri dev` 构建的桌面端用独立临时 Vault 打开原文成功；这是冒烟验证，不是原生翻译/滚动 A/B。本轮不改逐页预览 PNG 的生成和保留策略，也未测进程 RSS、原生翻译卡顿或 Windows。
