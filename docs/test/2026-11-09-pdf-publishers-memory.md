## 实测修复

- 整栏检测框与独立参考文献段落重叠时，完整小段落优先领取字符；紧邻段首的编号保留在本段。Oxford 的五处漏挂链接恢复为 85/85。
- 没有领取任何字符的重叠检测框，其文本已被同区域多个段落完整覆盖时不重复插入。PLOS 的重复参考文献及相应漏链接消除。
- 正文行中的 `figure 5` 不再恢复为独立图注；旧缓存的该类自动图注也会清理。文字几何版本 3→4，只重走文字，不重跑版面模型。Cambridge 新进程复测为 189/189。
- PDFium 生成的空白 advance 与可见字符重叠时，链接解析不把 `28` 拆成 `2 8`。保留数字之间真实的空白和多编号区间语义。
- 支持 AIP 带上标、无句点的参考文献编号，以相邻连续编号和共同栏边界验证，避免把普通指数当文献条目。
- PDF 字符串目标名使用 `decodeText()`，兼容 Frontiers 的 UTF-16 hex string；扩展 Cambridge、Frontiers、Wiley/IET、AIP 和 PLOS 的实际目标命名。作者年份目标的数字后缀只作标识，不擅自解释为印刷编号。
- 引用 sidecar 只有编号、没有题名或原始条目时，回退原文裁剪，避免空元数据卡挡住可读预览。作者年份裁剪支持作者缩写、首行缩进和下一行才出现年份的条目，避免串入下一篇或截断正文；正文姓氏可匹配参考文献的名字在前格式，仍要求同页唯一的作者 / 年份匹配。BERT 的 Williams、Zellers、Peters 三种实际引用恢复预览。
- 图号与目标页上已知图注冲突时不对准另一幅图；保留原链接目标页作为原文上下文。

## 已知源文件与版式边界

完整链接扫描不等于预览正确，更不等于逐字、逐页人工校对。悬停必须再核对内容、目标和异步图片完成状态。

- AIP 有 8 个命名目标无法由原 PDF 正常解析（`lcor1` 三处、`a` 五处）；Oxford 有一个 `UNDEFINED`。用 PyMuPDF 独立核对，不计作阅读器漏挂。
- IOP 有 28 处同位置同目标重复标注和三处错位链接，命中正文邻字而非实际图号/引文；源文件提取同样如此。该样本不列为所有引用完全通过。
- PLOS 有一处宽度为零的空标注；`Fig 13` 的原生目标落在第 20 页，而实际图在第 22 页。预览与点击保留源链接，不把第 20 页的图 11 假称为图 13。
- RSC 和 Sage 样本没有原生内部链接，只验收正文与图像，不能计作引用恢复通过。
- Elsevier 的一个公式编号与公式分离显示，内容仍可读，版式不等同原 PDF。

## 内存改动与对照方法

普通文字页不再无条件生成 2×整页 RGBA；仅非绘制文字或特殊变换文字需要墨迹判断时生成。字符样式按文档共享，123 页样本 217,701 个字符使用 71 个样式对象。无原生链接的段落不再构造一份完整链接字形模型，裸 URL 仍可点击。

阅读图像使用 Blob URL，在视口外 500px 预取范围之外释放；重新进入时再请求裁剪。尺寸占位保持，迟到异步结果和卸载后结果不再挂载。公式 mask 编码在成功和失败路径都关闭 ImageBitmap 并清空画布。单栏阅读卸载隐藏 PDF 页面的底图、瓦片和文字层，保留滚动几何与导航；分屏和退出阅读模式恢复源页绘制。

每组内存对照均重启 Host/WebKit，使用相同四篇 123/9/13/8 页论文、相同版面缓存、三轮共 12 次打开，每轮关全部测试 PDF，最后等待 30 秒。无引擎诊断钩子、无强制 GC；比较 WebKit 页面进程 RSS 与内核最高 RSS，不混用 WebKit footprint 或整机内存。

| 阶段 | RSS 采样峰值 | 内核最高 RSS | 最终关闭后 RSS |
|---|---:|---:|---:|
| 本轮优化前 | 1,916 MiB | 1,983 MiB | 1,196 MiB |
| 跳过普通页光栅 + Blob 生命周期 | 1,965 MiB | 2,070 MiB | 1,079 MiB |
| 再加样式共享、链接模型和 mask 释放 | 1,999 MiB | 2,029 MiB | 1,146 MiB |

这三组没有证明峰值明显下降；不能将对象数减少等同于进程内存峰值降低。

### 隐藏源页绘制的单变量对照

最终其余源码相同，仅切换 `renderPage` 在单栏阅读时是否挂载 `PdfPageLayers`。四篇都预热至文字几何版本 4，每组均为新进程、三轮 12 次打开、每轮关全部测试 PDF、最后等 30 秒；不修改源码或文档，不执行引擎诊断，不强制 GC。两个实验保留相同的 Library 与一个未挂载 PDF 的历史库页标签。

| 指标 | 保留隐藏源页绘制 | 单栏卸载源页绘制 |
|---|---:|---:|
| 采样跨度（秒） | 296.1 | 278.8 |
| WebKit RSS 采样峰值（MiB） | 5,204.6 | 1,871.3 |
| 内核最高 RSS（MiB） | 5,236.2 | 1,886.9 |
| 匿名私有脏页峰值（MiB） | 4,969.3 | 1,637.2 |
| Host 最终 RSS（MiB） | 349.0 | 344.9 |
| 第一轮关闭后 RSS（MiB） | 1,121.7 | 888.9 |
| 第二轮关闭后 RSS（MiB） | 1,976.6 | 1,217.1 |
| 第三轮关闭后 RSS（MiB） | 4,720.4 | 1,314.5 |
| 最终等待后 RSS（MiB） | 4,620.0 | 1,057.9 |

同一负载中，卸载隐藏源页绘制后的内核最高 RSS 为 1,886.9 MiB，最终关闭后为 1,057.9 MiB；对照组分别为 5,236.2 / 4,620.0 MiB。对照组在第二轮后明显增长，第三轮关后仍残留较多，不能拿单组差额直接宣传稳定节省百分比。三个更早阶段的峰值约 2 GiB，也说明这一增长并非每次短测都会出现。

再用新 Host / WebKit 重复优化组三轮：282.3 秒、12 次打开，RSS 采样峰值 1,774.0 MiB、内核最高 1,933.0 MiB、最终等待后 1,073.1 MiB；每轮关闭后的 RSS 为 891.4 / 988.4 / 1,287.6 MiB。两次优化组均未复现该次对照的 5 GiB 增长，支持保留这项资源优化，但不足以证明跨机器、长时间运行时稳定或历史异常已根治。

三组每篇的块数和字符数完全一致，单组内 PID 与页面存活标记未变，无崩溃 / 刷新；Host 最终 RSS 约 345–351 MiB。没有靠少加载正文换取内存下降。最终源码逐字节恢复并核对 SHA-256。关闭后约 1 GiB 的残留以及对照的非稳定增长仍需更长时间与分配器层取证，不能自动认定为正常缓存，也不能直接归给 PDFium。

历史 8,192 MB 是 WebKit 的 footprint 保护阈值，不能解释成应用要求 8 GB 内存。历史 9,408/10,429 MB 超限退出未在干净对照中重现，仍不能确定归因于新增功能还是原有问题。旧前端同 Host 与当前 PDF 的内存相近、连续阅读增加内存成本，详见[前一轮对照](2026-11-09-pdf-delivery-memory.md)。Zotero 的历史报告和本机进程快照亦在那里，不能据此宣布当前 Zotero 普遍严重泄漏。
