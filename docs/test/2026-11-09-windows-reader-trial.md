- 最终 v2 源快照的 TypeScript 与 Vite 生产构建通过；49 个相关测试文件共 510 项，其中 507 通过、0 失败、3 项可选真实 PDF 测试跳过。原始记录为 `windows-tests-release.json`。不是全仓完整测试。

- 构建期不注入内置云服务或 telemetry 凭据，不生成上游 updater 签名；安装包准备内嵌 WebView2 引导程序。首次缺少 WebView2 或版面模型时需要联网。

## 中间包的原生检查

Windows release 编译及 NSIS 打包通过。安装包约 45.51 MiB，解包完整性检查通过；包含主程序、插件工作进程、PDFium 和应用资源。主程序依赖 MSVCP140，插件工作进程依赖 VCRUNTIME140，试用包额外携带 Microsoft 官方签名的 MSVCP140、VCRUNTIME140、VCRUNTIME140_1 DLL。

从安装包解出完整应用，在隔离的测试配置 / WebView2 数据目录中启动，使用 Windows 11、WebView2 157.0.4341.42、150% DPR 进行验证。不是开发服务器或独立网页，也没有执行 NSIS 安装向导来覆盖本机安装；另一台电脑的实际安装仍属于用户试用范围。

### 发现并修正的公式裁剪问题

Wiley/IET `10.1049/ell2.70574` 第 2 页的 `×10⁻⁵ Ω·` 等字形在 PDFium 透明画布路径中丢失，而同位置、相同尺寸的普通纸面裁剪完整。证据为 `rawtrue.png` / `rawfalse.png`，不能把它误判为正文模型缺字。

`renderPdfRegionImageBlob` 改为普通纸面合成，再用已有 `glyphMaskBlob` 去背景。保留透明输出、主题染色及画布释放行为；新增最小回归在修复前失败、修复后通过。真实桌面诊断对照确认恢复，再重新发布构建，最后从新包重新启动并复查。最终截图为 `smoke/iet-formula-packaged-final.png`。

### 明确保留的边界

Oxford 样本仍有 `AlphaFo ld`、`Stru ctu re` 等词内多余空格，前轮 `publishers/final/pub_oup-content.json` 中已经存在；部分上标或紧邻符号的细节仍不理想。本次修复公式透明裁剪，不扩大到整体文字拼接改造。不能据出版社覆盖和链接命中率称现代论文无损适配。

本次原生检查为短时冒烟，未证明长期内存稳定、8 GB 机器可用性或系统缩放完整矩阵。相关单点内存样本包含 Agent 自动探测等子进程，不作为阅读器独占内存基准。

## 持续试用与后续方向

重点记录以下场景：

1. 真实论文阅读、PDF / 单栏 / 分屏切换，引用预览、跳转和返回；多次开关标签后重新打开。
2. 125% / 150% 系统缩放、Ctrl+滚轮、调整窗口、退出和恢复阅读位置。
3. 连续 1–2 小时使用，期间关闭全部文档并等待；记录页面、GPU 和整个应用进程树的 private bytes 趋势。
4. 无缓存首次分析与缓存复用的耗时；完成模型下载后的断网本地阅读。

长期内存趋势优先于继续增加出版社名录。若仍出现基线持续增长，按页面、图形进程、ONNX 和 PDFium 生命周期分别取证；若长文首开明显慢，再依据实际耗时评估正文准备和可视区域调度。已有对象数优化不能代替进程内存实测，不能承诺任意现代论文完美适配或长期无泄漏。

试用包附只读内存采样脚本，记录进程数量、工作集、private bytes 和页面 / GPU 分类，不记录文档正文、账户或密钥。多进程工作集相加会重复计算共享页，优先比较同一机器上的 private bytes 趋势。

开发文档没有单独的 Roadmap / TODO 文件，本轮检查了[开发目录约定](../development/index.md)和 [PDF 限制与后续](../frontend/pdf.md)。用户持续试用后再整理提交和上游 PR；本轮不推送或发布。
